# Implementation Plan: Simulator-Verified Reasoning Distillation and Constrained PPO for HAPS-ISAC

## 1. Purpose

This document is the implementation roadmap for the freshness-aware and secure HAPS-ISAC resource-allocation problem developed in the accompanying system-model and optimisation documents. The intended training pipeline is:

```text
Numerical network state
        |
        v
Large reasoning teacher -> K high-level action candidates
        |
        v
Physics completion -> safety repair -> stochastic simulator verification
        |
        v
Verified demonstration dataset
        |
        v
4B-class Gemma student adapted by offline QLoRA/LoRA distillation
        |
        v
Active correction on difficult student-visited states
        |
        v
Constrained PPO refinement in the simulator
        |
        v
Deployed student + physics completion + safety layer
```

The large model is used only offline. It proposes high-level decisions, while the simulator remains the authoritative evaluator. Raw complex beamforming vectors are never generated by the language model. The primary deployed controller is an open-weight Gemma 4 E4B instruction model with a structured numerical action head, adapted through QLoRA/LoRA; the compact numerical actor-critic is retained only as a low-latency ablation.

---

## 2. Decisions Already Frozen

The following decisions should be treated as the initial design baseline.

1. **Teacher role:** offline reasoning-assisted candidate proposer.
2. **Verifier:** stochastic HAPS-ISAC simulator with hard-constraint checks and risk-sensitive rollout evaluation.
3. **Student:** 4B-class `google/gemma-4-E4B-it` with a structured hybrid-action head, adapted with QLoRA by default or BF16 LoRA when memory permits; the base model remains frozen.
4. **Training:** verified offline distillation, optional active teacher correction, and constrained PPO refinement.
5. **Deployment:** PEFT-adapted Gemma student, deterministic physics-completion module, and safety/repair layer only; a numerical-only policy is an explicit efficiency ablation.
6. **Action hierarchy:** the learned policy outputs high-level scheduling, power, RIS, mobility, and computing decisions. Beamformers and combiners are produced by deterministic wireless algorithms.
7. **Constraint handling:** hard constraints are repaired or rejected per slot; long-term constraints are represented by virtual queues and constrained PPO multipliers.
8. **Teacher selection:** Qwen and Gemma are compared on wireless-specific verified performance rather than chosen solely from general benchmarks.

---

## 3. Scope Control

### 3.1 Version 1: Minimum Viable Research Environment

Implement and validate the following first:

- one fixed full-duplex HAPS-ISAC base station with onboard processing;
- fixed near/far NOMA IoT pairs;
- pair-level TDMA scheduling;
- one mobile target/eavesdropper;
- communication and sensing power allocation;
- physics-based communication and sensing beamforming;
- target measurement, tracking covariance, and AoA/location uncertainty;
- AoI for legitimate IoT information;
- AoLI for information available to the target/eavesdropper;
- AoSI for the freshness of the latest usable target estimate;
- reliability, secrecy, sensing, power, and freshness constraints;
- virtual queues for long-term constraints;
- random, greedy, conventional PPO, and distilled-policy baselines.

### 3.2 Version 2: Progressive Extensions

Enable these components only after Version 1 passes all validation tests:

- aerial RIS with a finite phase/codeword library;
- cooperative AAV jamming and two-dimensional trajectory control;
- AAV propulsion and communication energy;
- residual full-duplex self-interference;
- imperfect CSI;
- imperfect NOMA SIC;
- blockage and probabilistic LoS/NLoS channels;
- robust evaluation under mismatched mobility and channel parameters.

### 3.3 Configuration Flags

Every extension should be switchable without changing source code:

```yaml
features:
  noma: true
  sensing: true
  target_tracking: true
  aerial_ris: false
  aav_jamming: false
  residual_self_interference: false
  imperfect_csi: false
  imperfect_sic: false
  stochastic_blockage: false
```

This staged design prevents several difficult subsystems from being debugged simultaneously and enables clean ablation experiments.

\[
c_t =

Long-term constraints should not be hidden only inside this weighted sum.

## 7. Phase 2: State and Action Schemas

### 7.1 Markov State

The internal simulator state may contain detailed complex-valued channel and estimator variables. The policy observation should contain a compact, sufficient, normalized representation.

Organize the observation into:

```python
observation = {
    "pair_tokens": float32[num_pairs, d_pair],
    "pair_mask": bool[num_pairs],
    "global_features": float32[d_global],
    "virtual_queues": float32[num_constraints],
    "previous_action": structured_or_flat,
}
```

### 7.2 Per-Pair Token

Each NOMA-pair token should initially contain:

- normalized effective direct-link gain for near user;
- normalized effective direct-link gain for far user;
- normalized RIS-assisted gain for each user when enabled;
- near/far user distance or path-loss feature;
- near/far AoI;
- packet availability or queue occupancy;
- time since latest generation for the head-of-line packet;
- previous-slot near/far rates;
- previous SIC margin;
- recent decoding-success indicators;
- optional shadowing/blockage state.

Avoid including both raw complex channels and every derived SINR feature. Preserve only the information necessary for scheduling and high-level power decisions. Raw complex channels remain inside the physics module.

### 7.3 Global Features

Include:

- normalized target position and velocity estimate;
- compact uncertainty representation, preferably the lower-triangular Cholesky entries of the tracking covariance;
- AoSI;
- target/eavesdropper information state needed for AoLI;
- HAPS residual-self-interference feature when enabled;
- AAV position, remaining energy, previous heading, and previous speed when enabled;
- current RIS codeword index or embedding input when enabled;
- normalized time within the episode if traffic or mobility is non-stationary;
- recent fallback/repair indicators;
- optional user-intent or priority weights if later studied.

### 7.4 Virtual Queues

For each long-term constraint \(j\), update

\[
Z_j[t+1]=\left[Z_j[t]+g_j(s_t,a_t)\right]^+.
\]

Candidate virtual queues include:

- reliability deficit;
- secrecy-outage deficit;
- sensing-outage deficit;
- tracking-uncertainty deficit;
- average AoLI/privacy deficit;
- energy-budget deficit.

Normalize virtual queues using fixed clipping thresholds and a monotone transform such as

\[
\widetilde Z_j=\frac{\log(1+Z_j)}{\log(1+Z_j^{\max})}.
\]

### 7.5 High-Level Action

The learned high-level action is

\[
a_t^H=(m_t,c_{R,t},\eta_H,\eta_c,\eta_n,\eta_J,\psi_J,\nu_J,\eta_f).
\]

| Variable | Type | Meaning | Transform |
|---|---|---|---|
| \(m_t\) | categorical | scheduled NOMA pair or sensing-only mode | softmax/sample |
| \(c_{R,t}\) | categorical | RIS codeword | softmax/sample |
| \(\eta_H\) | continuous | HAPS power utilization | sigmoid to \([0,1]\) |
| \(\eta_c\) | continuous | communication fraction; remainder is sensing | sigmoid to \([0,1]\) |
| \(\eta_n\) | continuous | near-user NOMA power fraction | bounded transform plus SIC repair |
| \(\eta_J\) | continuous | AAV jamming-power fraction | sigmoid to \([0,1]\) |
| \(\psi_J\) | continuous | AAV heading | \(\pi\tanh(x)\) |
| \(\nu_J\) | continuous | AAV speed fraction | sigmoid to \([0,1]\) |
| \(\eta_f\) | continuous | HAPS processing/CPU fraction | sigmoid to \([0,1]\) |

Disabled components are masked and assigned deterministic neutral actions.

### 7.6 Action Dataclasses

Use separate structures for:

```python
RawPolicyAction
TransformedHighLevelAction
CompletedPhysicalAction
RepairedExecutableAction
```

Never overwrite a raw action during transformation or repair. Retaining every version is necessary for calculating repair distance and diagnosing policy behaviour.

### 7.7 Completion Gate

Phase 2 is complete when random valid states and actions can be serialized, deserialized, batched, normalized, and reconstructed without information loss.

## 8. Phase 3: Core Simulator

### 8.1 Gymnasium Interface

Implement:

```python
observation, info = env.reset(seed=seed, options=scenario_options)

next_observation, reward, terminated, truncated, info = env.step(action)
```

The environment should also provide a pure evaluation function that does not mutate the original state:

```python
evaluation = env.evaluate_candidate(
    state=state_snapshot,
    high_level_action=action,
    rollout_seed=seed,
)
```

Use state cloning or immutable state snapshots for candidate comparison.

### 8.2 Required Slot Sequence

Each `step()` must execute in the following order:

1. validate and transform the raw high-level action;
2. construct communication, sensing, receive, and jamming beams;
3. select the RIS codeword;
4. project/repair the action into the feasible executable set;
5. generate or update channel realizations;
6. compute communication SINRs and NOMA decoding outcomes;
7. compute target/eavesdropper reception and secrecy quantities;
8. compute sensing SINR and measurement covariance;
9. generate the sensing measurement when detection succeeds;
10. perform target-tracker prediction and update;
11. process the sensing estimate at the HAPS;
12. update AoI, AoLI, and AoSI;
13. update target and AAV positions;
14. update AAV/HAPS energy states;
15. calculate instantaneous constraints;
16. update virtual queues;
17. calculate stage reward and per-constraint costs;
18. build and normalize the next observation;
19. populate the diagnostic `info` dictionary.

Document any one-slot timing convention explicitly. In particular, specify whether a packet or sensing estimate delivered during slot \(t\) resets its age at the end of slot \(t\) or the beginning of slot \(t+1\).

### 8.3 Diagnostic Information

At minimum, return:

```python
info = {
    "stage_cost": float,
    "sum_aoi": float,
    "mean_aoi": float,
    "aoli": float,
    "aosi": float,
    "secrecy_rate": float,
    "tracking_mse": float,
    "tracking_cov_trace": float,
    "communication_energy": float,
    "propulsion_energy": float,
    "sic_margin": float,
    "sensing_sinr": float,
    "reliability_violation": float,
    "secrecy_violation": float,
    "sensing_violation": float,
    "uncertainty_violation": float,
    "power_violation": float,
    "mobility_violation": float,
    "repair_distance": float,
    "hard_feasible": bool,
    "fallback_used": bool,
}
```

### 8.4 Vectorization

The environment must support multiple independent instances. Aim initially for 16 or 32 parallel CPU environments. Avoid Python loops over users inside the hottest SINR and reward calculations where vectorized tensor operations are possible.

### 8.5 Completion Gate

Phase 3 is complete when long random-policy rollouts run without NaNs, covariance failure, invalid ages, unbounded queues caused by coding errors, or nondeterministic results under fixed seeds.

## 9. Phase 4: Physics Completion

The policy outputs high-level variables. Convert them deterministically into physical controls.

### 9.1 Communication Beam

Start with a normalized MRT or regularized-ZF construction based on the selected pair's effective legitimate channels. The exact method should be configurable and later treated as an ablation.

### 9.2 Sensing Transmit Beam

Use the steering vector corresponding to the predicted target direction. If target uncertainty is large, optionally broaden or robustify the sensing beam using covariance-weighted angular samples.

### 9.3 Sensing Receive Combiner

Use matched filtering initially. Add MVDR after the sensing and self-interference covariance matrices are validated.

### 9.4 AAV Jamming Beam

Use MRT toward the estimated target/eavesdropper and, when required, null or limit leakage toward legitimate IoT devices.

### 9.5 RIS Codebook

Generate the codebook offline using one of:

- quantized geometric steering directions;
- DFT beams;
- clustered channel/statistical directions.

Each codeword must satisfy the unit-modulus or discrete-phase hardware constraint. Store a codebook hash with every experiment.

### 9.6 AAV Velocity

Convert heading and normalized speed into

\[
\mathbf v_J[t]
=v_{\max}\nu_J[t]
\begin{bmatrix}
\cos\psi_J[t]\\
\sin\psi_J[t]
\end{bmatrix}.
\]

### 9.7 Completion Gate

Phase 4 is complete when every valid high-level action maps to a dimensionally and physically consistent completed action before safety repair.

## 10. Phase 5: Safety and Repair Layer

### 10.1 Hard Constraints

Immediately enforce:

- HAPS total-power limit;
- communication/sensing power simplex;
- AAV jamming-power limit;
- RIS phase/codeword feasibility;
- NOMA power bounds;
- minimum SIC feasibility where repair is possible;
- AAV speed and displacement limits;
- AAV operational-region boundaries;
- instantaneous battery/energy availability;
- finite CPU/processing capacity.

### 10.2 Repair Order

Use a deterministic repair order:

1. clip normalized variables;
2. project power variables;
3. repair the NOMA split for SIC feasibility;
4. enforce minimum sensing allocation if the state requires urgent sensing;
5. project AAV motion into its speed and region limits;
6. reduce jamming or motion according to energy availability;
7. verify all hard constraints;
8. invoke a safe fallback if feasibility is still not achieved.

### 10.3 Safe Fallback

Define at least one guaranteed executable fallback, for example:

- sensing-only with a conservative beam when tracking uncertainty or AoSI is critical;
- communication-only to the most urgent feasible pair when sensing is safe;
- zero AAV motion and zero jamming under battery exhaustion.

### 10.4 Repair Distance

Calculate a normalized repair distance:

\[
d_{\mathrm{rep}}
=
\sum_{d\in\mathcal D_c}
\omega_d|a_d^{\mathrm{raw}}-a_d^{\mathrm{rep}}|
+\sum_{d\in\mathcal D_k}
\omega_d\mathbb I(a_d^{\mathrm{raw}}\neq a_d^{\mathrm{rep}}).
\]

Teacher candidates requiring less repair should be preferred when verified costs are similar.

### 10.5 Completion Gate

Phase 5 is complete when one million randomly sampled high-level actions either produce an executable repaired action or invoke a documented fallback without crashing.

## 11. Phase 6: Unit and Integration Validation

### 11.1 Required Unit Tests

**Channels**

- received average power decreases with distance under fixed conditions;
- LoS/NLoS and path-loss conversions match hand calculations;
- zero transmit power produces zero desired signal power;
- complex vector and matrix dimensions are correct.

**NOMA**

- decoding order is implemented as specified;
- SIC feasibility margins match independent calculations;
- rates reduce correctly when interference increases;
- the repaired power split satisfies configured bounds.

**Freshness**

- AoI increments by one slot when no useful packet is delivered;
- successful delivery resets AoI to the correct system/packet delay;
- AoLI follows the intended eavesdropper update event;
- AoSI resets only when a newly processed usable estimate is available;
- sensing delay and onboard processing delay are included consistently.

**Tracking**

- covariance remains symmetric positive semidefinite;
- prediction increases uncertainty in the absence of measurements;
- a high-quality measurement reduces posterior uncertainty;
- target state transitions match the configured mobility model.

**Environment**

- reset and step conform to Gymnasium;
- fixed seed gives bitwise-identical or tolerance-identical trajectories;
- cloned states are unaffected by candidate evaluation;
- episode termination and truncation are correct.

### 11.2 Small-Scale Oracle Tests

For one pair, a tiny RIS codebook, and discretized power levels, enumerate the action space. Compare:

- best one-step action;
- teacher-selected action;
- greedy action;
- learned student action.

The oracle is not a full-system baseline, but it reveals simulator, verifier, and reward errors.

### 11.3 Completion Gate

No teacher API calls should be made until all critical tests pass and the small-scale oracle produces physically interpretable decisions.

## 12. Phase 7: Baseline Controllers

Implement baselines before generating the final teacher dataset.

1. **Random feasible policy:** samples high-level actions, then uses repair.
2. **Urgency-greedy policy:** prioritizes a combination of AoI, AoSI, uncertainty, and virtual queues.
3. **Myopic optimization:** grid search, alternating optimization, SCA, or another tractable one-slot method.
4. **Conventional PPO from scratch:** same numerical architecture as the final student, without teacher initialization.
5. **Existing HDRL-style baseline:** if compatible with the action hierarchy.
6. **Teacher direct deployment:** teacher candidates plus simulator verification; used only as an offline upper-reference because latency is high.

Baselines must use the same state information, physical completion, constraint definitions, scenario seeds, and evaluation horizon wherever possible.

## 13. Phase 8: Teacher Abstraction and Free-Access Strategy

### 13.1 Provider-Independent Interface

```python
class TeacherPolicy(Protocol):
    def propose(
        self,
        state_packet: dict,
        num_candidates: int,
        seed: int,
    ) -> list[TeacherCandidate]:
        ...
```

Each provider adapter must support:

- model identifier;
- prompt version;
- sampling controls;
- retry and timeout handling;
- JSON extraction and validation;
- token/latency accounting;
- response caching;
- optional reasoning-effort control.

### 13.2 Recommended Teacher Candidates

**Primary candidate:** Qwen3.5-27B with high or extra-high reasoning effort.

**Efficient alternative:** Gemma 4 26B-A4B.

**Secondary accuracy comparison:** Gemma 4 31B.

Use the current provider-specific model identifier in configuration rather than hard-coding a marketing name.

### 13.3 Access Plan

1. Prototype the complete teacher adapter using Gemma through the Gemini API free tier.
2. Use the Qwen Model Studio new-user quota for the teacher tournament if available.
3. Enable a hard stop at the free-quota limit whenever the provider supports it.
4. Move final large-scale generation to locally hosted open weights on the available research cluster.
5. Use vLLM, SGLang, or another OpenAI-compatible local server so the rest of the code remains unchanged.

Free hosted tiers are rate-limited and may change. They should be treated as prototyping resources rather than permanent experimental infrastructure.

### 13.4 Research Privacy

Only synthetic numerical state packets should be sent to hosted providers. Do not include credentials, unpublished manuscript text, participant data, or hidden system information in prompts. The dataset does not require storing hidden chain-of-thought. Store the final action, verification results, and optionally a short explicit decision summary.


The optional priority tags are auxiliary supervision, not control variables.

### 14.3 Prompt Rules

Tell the teacher to:

- respect all numerical bounds;
- prioritize hard feasibility;
- account for virtual queues;
- reason about the communication-sensing-security trade-off;
- avoid emitting beamformers or channel calculations;
- avoid text outside the JSON object;
- diversify candidates when multiple calls/samples are requested.

### 14.4 Error Handling

1. Parse strict JSON.
2. Validate against a schema.
3. Attempt one deterministic JSON-repair pass for formatting errors only.
4. Retry the teacher once with the validation error.
5. If still invalid, mark the candidate invalid and continue.
6. Never silently replace invalid numerical values with an apparently valid teacher label; safety repair remains visible in the record.

### 14.5 Cache Key

Hash:

```text
model_id + prompt_version + normalized_state_json + sampling_parameters + seed
```

The cache prevents repeated cost when jobs restart and makes experiments reproducible.

## 16. Phase 11: Stochastic Rollout Verification

### 16.1 Candidate Evaluation

For state \(s_t\), teacher candidate \(a_t^{(k)}\):

1. transform the candidate;
2. complete physical controls;
3. repair hard violations;
4. simulate the repaired first action;
5. continue for \(H-1\) slots using a fixed rollout policy;
6. repeat under \(M\) common random seeds;
7. aggregate reward, risk, constraints, and repair distance.

The continuation policy can initially be the urgency-greedy baseline. Later, replace it with the latest student policy.

### 16.2 Risk-Sensitive Cost

For rollout costs \(C_{k,1},\ldots,C_{k,M}\), calculate

\[
\widehat C_k^{\mathrm{risk}}
=(1-\beta)\frac{1}{M}\sum_{m=1}^M C_{k,m}
+\beta\,\widehat{\mathrm{CVaR}}_{\alpha}
\left(C_{k,1:M}\right).
\]

Start with \(\alpha=0.9\). Tune \(\beta\) using validation scenarios.

### 16.3 Lexicographic Selection

Select

\[
k^*=\arg\min_k
\left(
V_k^{\mathrm{hard}},
\widehat C_k^{\mathrm{risk}},
d_{\mathrm{rep},k}
\right).
\]

That means:

1. feasible candidates dominate infeasible candidates;
2. among feasible candidates, lower risk-sensitive cost wins;
3. close costs are resolved in favour of smaller repair.

### 16.4 Quality Weights

Do not necessarily discard all non-winning feasible candidates. Assign

\[
q_k=
\frac{\exp[-(\widehat C_k^{\mathrm{risk}}-C_{\min})/\tau_q]}
{\sum_{i\in\mathcal F}\exp[-(\widehat C_i^{\mathrm{risk}}-C_{\min})/\tau_q]},
\]

where \(\mathcal F\) is the feasible candidate set. This supplies richer supervision than a single hard label.

### 16.5 Computational Controls

- vectorize candidate rollouts;
- use common random numbers;
- cache identical state-action evaluations;
- use smaller \(H\) and \(M\) during pipeline debugging;
- reserve full verification for the retained dataset;
- profile simulator throughput before scaling teacher generation.

## 18. Phase 13: Student Architecture

### 18.1 Primary 4B Student (Gemma 4 E4B-it)

Use `google/gemma-4-E4B-it` as the primary student backbone. It is a 4B-class choice: E4B denotes roughly 4.5B effective parameters (the full model is roughly 8B including embeddings), so reports must not call it exactly 4B total.

**Model choice and input**

- load the instruction-tuned checkpoint and run it in text-only mode;
- serialize the same causal state packet used by the teacher into a deterministic, versioned textual representation;
- do not distill hidden chain-of-thought or teacher rationale; distill only simulator-verified executed actions and targets.

**Structured policy interface**

- read the final hidden state at an `<ACTION>` sentinel (or equivalent pooled state);
- attach scheduling/pair-selection logits, RIS-codebook logits, seven bounded continuous-action distribution heads, a value head, and constraint-risk heads;
- expose one joint action distribution so the same checkpoint has native log-probabilities for PPO;
- keep physics completion, deterministic repair, and safe fallback outside the learned head.

**Parameter-efficient updates**

- default to QLoRA: frozen 4-bit NF4 Gemma base, BF16 compute, trainable LoRA adapters plus the structured action/value heads;
- use BF16 LoRA without quantization when memory permits; never full-finetune the 4B-class base in the initial pipeline;
- start with LoRA rank 16, alpha 32, dropout 0.05 on attention projections (`q_proj`, `k_proj`, `v_proj`, `o_proj`), then tune by validation;
- save the frozen base revision, tokenizer, adapter, heads, and distillation/PPO configuration together as one reproducible checkpoint.

### 18.2 Optional Numerical Student Baseline

Use a compact numerical set/attention actor-critic as an explicitly labelled low-latency and memory-efficiency ablation.

**Pair encoder**

\[
d_{\mathrm{pair}}\rightarrow64\rightarrow64
\]

with a shared MLP applied to every NOMA pair.

**Set encoder**

- two self-attention or Set-Transformer blocks;
- embedding dimension 64;
- four attention heads;
- mask support for a variable number of pairs;
- attention pooling to one 64-dimensional network representation.

**Global encoder**

\[
d_{\mathrm{global}}+d_{\mathrm{queues}}
\rightarrow128\rightarrow128.
\]

**Actor trunk**

\[
192\rightarrow256\rightarrow256.
\]

**Action heads**

- scheduling logits: `num_pairs + optional_sensing_only`;
- RIS logits: `codebook_size`;
- continuous distribution parameters for the seven continuous actions;
- optional priority-tag auxiliary classifier.

**Critics**

- scalar return/value critic;
- one shared multi-output constraint critic or separate critics for reliability, secrecy, sensing, uncertainty, and energy risks.

The expected parameter count is approximately 0.5-2 million, depending on the number of features and critic sharing.

### 18.3 Shared Continuous Distributions

Use either:

- beta distributions for naturally bounded ([0,1]) controls; or
- Gaussian variables in unconstrained space followed by sigmoid/tanh transforms.

The log-probability calculation used by PPO must include the transform Jacobian. Do not clip Gaussian samples after sampling without correcting their probability.

### 18.4 Optional Pure-JSON LLM Ablation

An autoregressive JSON-generating Gemma 4 E4B or small Qwen student may be evaluated as a secondary ablation. It is not the primary controller because token generation is slower, continuous control is unnatural, malformed outputs remain possible, and token-level PPO is significantly more expensive than the structured action head.

## 19. Phase 14: Offline Distillation

### 19.1 Losses

Distillation is action-level parameter-efficient fine-tuning, not transfer of teacher parameters or hidden reasoning. Each example contains the causal state text, the simulator-verified executed action (or soft practical-equivalence candidates), quality weights, return/cost targets, and constraint outcomes.

The Gemma backbone is loaded once, kept frozen, and augmented with the structured hybrid-action/value/constraint heads. In QLoRA mode the base is loaded in 4-bit NF4 with BF16 compute. Gradients update only LoRA adapter matrices and the newly initialized heads; the tokenizer, frozen base revision, adapter, and heads are saved together.

The action heads produce categorical logits and continuous distribution parameters directly, so the loss trains the same joint distribution later consumed by PPO. No teacher gradient, chain-of-thought, or generated rationale is required.

Use

\[
\mathcal L_{\mathrm{distill}}
=\lambda_{\mathrm{cat}}\mathcal L_{\mathrm{cat}}
+\lambda_{\mathrm{cont}}\mathcal L_{\mathrm{cont}}
+\lambda_V\mathcal L_V
+\lambda_C\mathcal L_C
+\lambda_{\mathrm{aux}}\mathcal L_{\mathrm{aux}}.
\]

Where:

- \(\mathcal L_{\mathrm{cat}}\): quality-weighted cross-entropy for scheduling and RIS;
- \(\mathcal L_{\mathrm{cont}}\): negative log likelihood of verified continuous actions;
- \(\mathcal L_V\): regression to verified rollout return/cost;
- \(\mathcal L_C\): prediction of constraint costs or violation probabilities;
- \(\mathcal L_{\mathrm{aux}}\): optional priority-tag or urgency prediction.

### 19.2 Quality-Weighted Behaviour Cloning

For candidates \(a_{i,k}\) with weights \(q_{i,k}\):

\[
\mathcal L_{\mathrm{policy}}
=-\sum_i\sum_{k\in\mathcal F_i}
q_{i,k}\log\pi_\theta(a_{i,k}\mid s_i).
\]

This allows the student to learn a distribution over similarly good actions rather than overfitting to arbitrary tie-breaking.

### 19.3 Training Defaults

Starting values:

```yaml
distillation:
  optimizer: adamw
  learning_rate: 3.0e-4
  weight_decay: 1.0e-4
  batch_size: 512
  max_epochs: 200
  gradient_clip_norm: 1.0
  early_stopping_patience: 20
  categorical_label_smoothing: 0.02
student:
  model_family: gemma4
  model_id: google/gemma-4-E4B-it
  model_revision: main
  parameter_class: "4.5B effective (~8B including embeddings)"
  input_mode: causal_state_text
  output_mode: structured_hybrid_action_head
  max_sequence_length: 4096
  train_action_head: true
peft:
  method: qlora
  quantization: nf4
  load_in_4bit: true
  compute_dtype: bfloat16
  freeze_base_model: true
  lora_rank: 16
  lora_alpha: 32
  lora_dropout: 0.05
  target_modules: [q_proj, k_proj, v_proj, o_proj]
  gradient_checkpointing: true
  fallback_method: lora
```

Tune loss weights so that no single head dominates the total gradient norm.

### 19.4 Validation Metrics

- scheduling top-1 and top-k agreement;
- RIS agreement;
- continuous-action MAE;
- action negative log likelihood;
- hard-feasible rate after completion/repair;
- mean repair distance;
- verified rollout cost;
- constraint-risk calibration;
- inference latency.

Teacher-action accuracy is secondary to verified closed-loop performance.

### 19.5 Completion Gate

The distilled student should substantially outperform random and greedy policies and approach the verified teacher on held-out states before PPO refinement begins.

## 20. Phase 15: Active Teacher Correction

Pure offline imitation can suffer from covariate shift because the student visits states absent from the teacher dataset.

### 20.1 Query Triggers

Query the teacher when one or more conditions hold:

- high predictive entropy in scheduling/RIS heads;
- high continuous-action variance;
- high predicted constraint risk;
- observation outside the training-feature support;
- large repair distance;
- fallback activation;
- rapidly growing virtual queue;
- student cost substantially worse than the greedy baseline;
- disagreement among an ensemble of student checkpoints.

### 20.2 Iteration

1. Roll out the current student.
2. Rank encountered states by uncertainty/risk.
3. Query the teacher only for the highest-value states.
4. Verify candidates using the simulator.
5. Add accepted records to the dataset.
6. Retrain or fine-tune the student.
7. Repeat for two to five rounds.

Start with 500-1,000 new states per active round. Stop when additional teacher queries produce negligible validation improvement.

## 21. Phase 16: Constrained PPO Refinement

### 21.1 Purpose

Distillation gives the student a strong initial policy. PPO then allows it to learn from its own state distribution, correct teacher imperfections, optimize long-horizon consequences, and potentially outperform the verified teacher candidate set.

The teacher is absent during PPO.

#### PPO initialization and PEFT updates

Load the identical frozen Gemma base revision, tokenizer, LoRA/QLoRA adapter, and structured action/value heads produced by distillation. Create a fresh PPO optimizer, but mark only the adapter matrices, action heads, and critic heads as trainable; the quantized/BF16 base remains frozen. The environment action distribution and log-probability calculation must be shared between distillation and PPO, including the continuous-transform Jacobians.

Keep the deterministic completion and hard safety repair active during rollouts. Store the pre-update log-probability from the structured joint head, compute simulator rewards and constraint costs, and update the PEFT parameters with the clipped PPO objective plus the decaying distillation anchor. Teacher calls are not part of PPO.

### 21.2 PPO Objective

Let

\[
\rho_t(\theta)=
\frac{\pi_\theta(a_t\mid s_t)}
{\pi_{\theta_{\mathrm{old}}}(a_t\mid s_t)}.
\]

Use the clipped objective

\[
\mathcal L_{\mathrm{clip}}
=-\mathbb E_t
\left[
\min\left(
\rho_t\widehat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\widehat A_t
\right)
\right].
\]

### 21.3 Constraint Handling

For constraint costs \(c_{j,t}\), maintain multipliers

\[
\lambda_j\leftarrow
\left[
\lambda_j+\eta_\lambda(\widehat J_{C_j}-d_j)
\right]^+.
\]

The policy advantage may be constructed as

\[
\widehat A_t^{\mathrm{safe}}
=\widehat A_t^{R}
-\sum_j\lambda_j\widehat A_t^{C_j}.
\]

Hard instantaneous feasibility remains the responsibility of the repair layer. PPO and virtual queues address expected or long-term constraints.

### 21.4 Distillation Anchor

Initially retain

\[
\mathcal L_{\mathrm{total}}
=\mathcal L_{\mathrm{PPO}}
+\lambda_{\mathrm{BC}}(n)\mathcal L_{\mathrm{distill}}
+\mathcal L_{\mathrm{value}}
+\mathcal L_{\mathrm{constraint}}.
\]

Decay \(\lambda_{\mathrm{BC}}(n)\) over training. A possible schedule is linear decay from 1.0 to 0.05 over the first 30-50% of PPO updates, followed by a small residual anchor.

### 21.5 Starting Hyperparameters

```yaml
ppo:
  num_parallel_envs: 32
  rollout_steps_per_env: 256
  gamma: 0.995
  gae_lambda: 0.95
  clip_epsilon: 0.20
  policy_learning_rate: 3.0e-4
  critic_learning_rate: 3.0e-4
  dual_learning_rate: 1.0e-3
  update_epochs: 10
  minibatch_size: 1024
  entropy_coefficient: 0.01
  value_coefficient: 0.5
  max_gradient_norm: 0.5
  target_kl: 0.02
  total_environment_steps: 5.0e6
```

These are starting values. Validate the discount factor against the slot duration and intended freshness horizon.

### 21.6 Monitoring

Track separately:

- task return;
- each physical cost;
- each constraint cost;
- each dual multiplier;
- virtual-queue lengths;
- policy entropy by action head;
- approximate KL divergence;
- clip fraction;
- repair distance;
- fallback frequency;
- action saturation;
- teacher-anchor loss.

Stop or roll back an update if KL divergence, violation rates, or fallback frequency changes abruptly.

### 21.7 Completion Gate

Constrained PPO is complete when the final student improves verified long-horizon cost over pure distillation without obtaining that improvement through increased constraint violations.

## 24. Failure Modes and Mitigations

| Risk | Detection | Mitigation |
|---|---|---|
| teacher produces attractive but infeasible numbers | low pre-repair feasibility, large repair distance | strict schema, verifier, feedback retry, physics completion |
| free API quota is exhausted | usage accounting | caching, hard quota stop, local open-weight inference |
| teacher calls dominate runtime | latency/tokens per accepted record | batch/local serving, active querying, smaller candidate count during debug |
| simulator contains a modelling error | failed oracle/unit tests | validate each subsystem before data generation |
| student memorizes teacher states | train/test gap | scenario-level splitting and OOD evaluation |
| student encounters unseen states | high uncertainty/fallback | active teacher correction and PPO |
| PPO forgets distilled behaviour | rising BC loss/KL and violations | decaying BC anchor, lower learning rate, rollback checkpoints |
| PPO reward hacking | improved reward but worse physical metrics | expose all metrics, constraints, and safety audits |
| one reward term dominates | gradient and cost-scale imbalance | physical normalization and per-term monitoring |
| virtual queues explode | queue trajectories | adjust thresholds, scaling, dual rate, and feasibility assumptions |
| target covariance becomes invalid | PSD/symmetry checks | Joseph-form EKF update, numerical stabilization |
| action heads saturate | near-zero entropy or boundary frequency | entropy scheduling, better transforms, normalization |
| multi-teacher dataset is inconsistent | multimodal labels and high NLL | retain soft candidate weights and simulator scores |

## 28. Expected Research Claims if Results Support Them

The intended claims should remain conditional until demonstrated experimentally:

1. Simulator verification converts general-purpose LLM reasoning into physically meaningful wireless-control supervision.
